1. PROJECT OVERVIEW
───────────────────────────────────────────────────────────────────────────────

The WordPress Health Guardian is an AI agent that:

  • Monitors WordPress site health (uptime, SSL, DNS, WP endpoints)
  • Uses Google Gemini for intelligent analysis
  • Integrates with Dynatrace MCP for deep observability (optional)
  • Generates structured health reports with scores & recommendations
  • Provides a clean web UI dashboard

Tech Stack:
  • Google ADK (Agent Development Kit) — agent framework
  • Gemini 2.5 Flash — LLM
  • Dynatrace MCP — observability integration
  • FastAPI + HTML/CSS — web UI
  • Cloud Run — deployment target

Judging criteria addressed:
  • Technological Implementation — ADK + Gemini + Dynatrace MCP + Cloud Run
  • Design — Clean dark-mode web UI with score visualization
  • Potential Impact — 60M+ WordPress sites need monitoring
  • Quality of the Idea — Novel AI agent + observability for WordPress

───────────────────────────────────────────────────────────────────────────────

File structure:
  wordpress-health-guardian/
    agent/
      main.py                 — ADK agent definition

        health_check.py       — uptime, SSL, DNS, WP endpoint checks
        analyzer.py           — report generation & markdown formatting
        dynatrace_tools.py    — Dynatrace MCP integration
    web/
      server.py               — FastAPI REST server
      static/index.html       — Web UI dashboard
    deploy/
      Dockerfile              — container for Cloud Run
      cloudbuild.yaml         — CI/CD pipeline
    tests/
      test_agent.py           — 6 unit tests (all passing)
    app.py                    — entry point
    requirements.txt          — Python dependencies
    README.md                 — full project documentation
    LICENSE                   — MIT license

Key agent tools:
  1. check_site_uptime(url)        — HTTP status & response time
  2. check_ssl_certificate(host)   — SSL expiry check
  3. check_dns_resolution(host)    — DNS resolution
  4. check_wordpress_specific(url) — /wp-admin, /wp-json, etc.
  5. generate_health_report(...)   — structured report builder
  6. format_report_for_display()   — markdown formatter
  7. check_dynatrace_config()      — checks DT env vars
  8. [Dynatrace MCP tools]         — problems, vulnerabilities, DQL (if configured)

7. STEP 4: SET UP DYNATRACE TENANT (HIGHLY RECOMMENDED)
───────────────────────────────────────────────────────────────────────────────

  Dynatrace integration is what makes your submission stand out.
  Without it, you still have a functional agent, but WITH it you
  demonstrate the full partner MCP integration required for the track.

  Setup:
    1. Go to https://www.dynatrace.com/signup/ (free trial, no credit card)
    2. After signup, you get a Dynatrace Platform URL like:
       https://abc12345.apps.dynatrace.com
    3. Generate a Platform Token:
       - Settings → Integration → Platform Tokens
       - Create token with permissions:
         • mcp-gateway:servers:invoke
         • mcp-gateway:servers:read
         • storage:logs:read (for DQL queries)
    4. Add to .env:
       DT_ENVIRONMENT=https://abc12345.apps.dynatrace.com
       DT_PLATFORM_TOKEN=dt0c01...your-token

  For demo purposes you can also:
  • Use the Dynatrace Playground: https://playground.apps.dynatrace.com
    (Note: may have limited data, but good for testing MCP connection)


8. STEP 5: TEST THE AGENT LOCALLY
───────────────────────────────────────────────────────────────────────────────

  Create .env file first (see steps above), then:

    cd C:\Users\Toks\Documents\Apps\wordpress-health-guardian
    python app.py

  This starts the server at http://localhost:8080

  Open your browser and:
  1. Enter a URL (e.g., https://wordpress.org)
  2. Click "Run Health Check"
  3. The agent will check uptime, SSL, DNS, WordPress endpoints
  4. It will generate a report with health score

  You can also test the API directly:
    curl http://localhost:8080/api/check?url=https://wordpress.org

  To run tests:
    python -m pytest tests/ -v

  NOTE: If you get API key errors, make sure .env is in the
  root directory and GOOGLE_API_KEY is set correctly.


9. STEP 6: DEPLOY TO CLOUD RUN
───────────────────────────────────────────────────────────────────────────────

  Prerequisites:
  • Google Cloud CLI installed and authenticated
  • Billing enabled on your project
  • Required APIs enabled:
      gcloud services enable run.googleapis.com
      gcloud services enable cloudbuild.googleapis.com
      gcloud services enable artifactregistry.googleapis.com
      gcloud services enable aiplatform.googleapis.com

  Deploy:
    gcloud run deploy wordpress-health-guardian ^
      --source . ^
      --region=us-central1 ^
      --allow-unauthenticated ^
      --set-env-vars=GOOGLE_API_KEY=AIza...your-key

  If you have Dynatrace configured, also add:
      --set-env-vars=DT_ENVIRONMENT=https://... ^
      --set-env-vars=DT_PLATFORM_TOKEN=dt0c01...

  After deployment, you'll get a URL like:
    https://wordpress-health-guardian-xxxxx-uc.a.run.app

  Keep this URL — you need it for the submission!

12. FAQ
───────────────────────────────────────────────────────────────────────────────

  Q: I don't have a Dynatrace tenant. Can I still submit?
  A: Yes, the agent works without Dynatrace (basic health checks +
     Gemini analysis). But for the Dynatrace track, you need MCP
     integration. Get a free trial at dynatrace.com/signup.

  Q: Can I use Claude/Cursor/Copilot?
  A: NO! The rules forbid competing AI tools. Only Google's
     tools are permitted (Gemini CLI, AntiGravity, etc.).

  Q: Can I submit from Nigeria?
  A: Check the rules. Nigeria is not in the excluded list.

  Q: Is my project eligible? It was created during the contest period.
  A: Yes, the project files were created on May 22, 2026, which is
     within the contest period (May 5 — June 11, 2026).

  Q: Can I have a team?
  A: Max 4 people. Currently you're solo. If you want teammates,
     find them before submitting.

  Q: How much does Cloud Run cost?
  A: With the free tier + $100 in credits, it will be free.
     The agent only runs when users make requests.

  Q: What if I can't deploy to Cloud Run?
  A: The hackathon says ADK agents can run locally. You can still
     submit with a local setup and show it working in the video.
